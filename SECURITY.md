# Security reporting

If you discover an access-control bypass, item duplication, network abuse, private snapshot exposure or another security issue, report it privately to the repository owner rather than opening a public issue with exploit details. Use GitHub private vulnerability reporting if the maintainer has enabled it, otherwise contact the owner directly.

Include the resource and WHIP dependency versions, the affected operation, impact and a minimal safe reproduction on a test server. Remove player identifiers, coordinates, private previews, credentials and other sensitive data. No response-time commitment or supported-version policy is established by this package.
